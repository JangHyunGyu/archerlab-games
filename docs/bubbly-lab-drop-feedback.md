# Forgiving bottle drops and target feedback

Drag targeting previously required the pointer itself to hit a bottle button. The new resolver uses both the pointer and the translated center of the dragged bottle, then accepts near misses up to 24 CSS pixels for mouse and 32 for touch/pen. Direct pointer hits take priority; padded hits use the closest rectangle, with center distance as a tie-breaker. Source slots participate in proximity so releasing near the original slot still cancels. Geometry never chooses a different receiver simply because it permits the move. Distant releases, off-screen pointers, invalid colors and full bottles retain their existing behavior.

Move highlighting and release use the same resolver. Geometry is captured once per gesture, with scroll/resize/blur/visibility changes cancelling the drag. A mint outline, a single expanding halo, a short upward bottle movement and a persistent arrow badge below the target identify a valid receiver. The badge was moved below the bottle after a browser capture showed the dragged glass covering the original badge above it. The marker also remains visible when that receiver is already pouring. Invalid receivers retain a rose outline. Reduced-motion preferences disable the transient effects while preserving the outline and arrow.

The original synthesized `target.wav` is a 140ms rising bubble pop. It plays only upon acquiring a valid receiver, respects mute/background settings, and is rate-limited to 120ms between changes. Remaining over a receiver neither replays audio nor restarts the animation. Existing pouring audio is unchanged.

Validation: all 56 game tests passed after the resolver change; the final focused drag/audio tests and TypeScript/Vite build plus rendered-output check passed after animation wiring. Tests cover exact vs padded hits, touch padding, nearest targets in gaps and multiple rows, offset grips, original-slot cancellation, invalid receivers, mouse/touch releases, duplicate click suppression, sound repeat suppression and scroll cancellation. An actual browser drag released 16px above the old button boundary successfully transferred liquid. Browser layout checks covered 320×568, 430×932, 768×1024, 1024×768, 667×375, 844×390, 1440×900 and dynamic-height 390×660: no horizontal overflow and all bottle/Home targets at least 44px and in view. No Korean copy changed.
