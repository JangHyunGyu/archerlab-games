# Zombie reward banking — 2026-10-04

Rerolled runs could lose their entire payout: the client sent the remaining run balance while the server compared it with gross kill rewards. A network failure could also leave final progress queued without a reward claim, and the old claim insert preceded a separate balance update. A failure between those writes left a claim marked complete without crediting the wallet.

The client captures the final kill/reward/reroll ledger before waiting and sends a durable `/school-zombie/profile/bank-run` command. Each successful reroll records its wave; the server recomputes the fixed price (5 × reroll number plus the stage surcharge). It credits the net balance to the existing profile, even without a ranking submission or a cleared stage. Older clients' net deductions are checked against costs achievable with at most one reroll per completed wave. New ledgers preserve their previously reported reroll prefix and reward counts.

Banking validates profile binding, reward count totals, unlocked reward types, coin arithmetic, minimum kills for the reached wave, stage/wave agreement and ledger continuity. Duration is display metadata and cannot reject banking or stage evidence. This is consistency validation of reported gameplay; combat is not simulated authoritatively on the server. Existing absolute reward limits remain. No backend version constants were changed.

The additive wallet update, unique session claim and final session ledger use one [transactional D1 batch](https://developers.cloudflare.com/d1/worker-api/d1-database/#batch). The update checks that the session has no claim before the claim is inserted. Rollback protects all three writes; a retry after a lost commit response reads the existing claim and cannot credit it twice. Two separate runs update the same wallet additively.

The bank command uses the same localStorage/IndexedDB journal and Durable Object alarms as rankings. Resetting the game, returning to the menu, closing the tab after server acceptance or reloading cannot overwrite its captured snapshot. Pending/review notices are distinct from a saved payout. Completion refreshes the current profile rather than applying an old stored receipt over later earnings or purchases. Game-over and menu balances refresh, and the new event listener is removed at scene disposal.

The browser verification never sends artificial progress, coins or rankings to production. Historical claims that already lack an identifiable payout cannot be safely compensated from current balances alone because purchases may have spent the money; this change does not guess refunds.
