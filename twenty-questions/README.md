# 스무고개 구현

한국어 `/twenty-questions/`, 영어 `/twenty-questions/index-en`에서 같은 게임을 제공한다. 정답은 서버가 선택하고 사용자는 질문과 정답 제출을 합쳐 20회 안에 맞힌다. 힌트는 없다.

## 확정한 동작

- D1에 초기 한영 정답 200개를 누적 보관. 사용자별 `tq_seen`에 배정 즉시 기록해 성공·실패·포기·날짜 변경 뒤에도 재출제 방지
- 미출제 개념만 무작위 선택. 저장된 목록을 한 번 섞어 소비하는 것과 같은 비복원 추출이며 전체 정답 목록은 클라이언트에 전달하지 않음
- 한 플레이어의 요청은 `TwentyQuestionsRoom` Durable Object가 직렬 처리. 중복 요청 ID·세션 버전·D1 트랜잭션으로 이중 차감과 중복 성공 방지
- 정답 제출은 등록된 한영 이름·동의어와 정확히 비교. 질문 판정은 Microsoft-Decision-1의 구조화된 판단 사용
- 예·아니오와 오답 제출은 1회 차감. 판정 보류·복수 질문·같은 질문 재사용·모델 오류는 기회 보존
- 20번째 정답 제출도 성공. 20번째 질문에 예를 받아도 별도 정답 제출 기회는 추가하지 않음
- 개인 최고 연속 성공 수로 순위 결정. 동률은 해당 기록의 총 사용 기회, 달성 시각 순
- 서버 판정 오류 시 세션 만료 시계 일시 정지. 복귀·언어 전환·재전송에서 과거 성공 효과 중복 재생 없음
- 포털의 기존 카드 순서를 유지하고 스무고개 카드 추가

## AI 연결

기존 `harem` 저장소의 `openrouter-api` Worker를 재사용한다. OpenRouter 키는 그 Worker에 그대로 두고 신규 게임에는 복사하지 않는다.

| 바인딩 | 기존 Worker의 진입점 | 용도 |
| --- | --- | --- |
| `TQ_AI` | `TwentyQuestionsAiEntrypoint` | Microsoft-Decision-1 / Azure 제공 경로에 고정한 판정 |
| `TQ_TEXT` | `DeepSeekTextEntrypoint` | 기존 텍스트 라우팅으로 신규 정답 후보 생성 |
| `TWENTY_GAMEPLAY` | `TwentyQuestionsRoom` | 플레이어별 동시 요청 처리 |
| `DB` | `archerlab_db` | 카탈로그·출제 이력·게임·랭킹 |

공용 AI Worker의 `TWENTY_QUESTIONS_DECISION_PRESET=microsoft-decision-azure`로 판정 경로를 관리한다. 새 RPC의 HTTP 진입은 404다. 하렘·큐피드의 기존 텍스트·이미지·방 모델 선택은 바꾸지 않는다.

직접 연결이 필요한 개발 환경에서는 `OPENROUTER_API_KEY`, 또는 `TQ_DECISION_PROVIDER=azure`와 `TQ_AZURE_ENDPOINT`, `TQ_AZURE_DEPLOYMENT`, `AZURE_API_KEY`를 사용할 수 있다. 서비스 바인딩이 있으면 기존 공용 Worker를 우선한다.

## 정답 보충과 보관

매일 04:00 KST에 재고를 확인한다. 최근 30일 활동 사용자 중 미출제 재고가 50개 미만이면 최대 25개 후보를 생성한다. 형식·기존 이름을 대조하고 Wikipedia 소개 문단을 확보한 뒤 그 출처로 사실 카드를 작성한다. 사실 일치와 기존 개념 중복을 별도 판정하고 두 검증 모두 유효한 수치 확률 0.97 이상일 때만 추가한다. 자동 생성 별칭은 사용하지 않으며 초기 검토된 동의어만 인정한다. 카탈로그가 커지면 중복 검증 입력을 바이트 예산에 맞춰 나눈다.

같은 날짜에는 한 보충 작업만 실행한다. 실패하면 기존 카탈로그를 유지하고 다음 날 다시 시도한다. 정답을 매일 삭제·교체하지 않는다. 사용자가 모두 소진한 경우 새 단어를 기다리며 연속 기록은 보존한다. 기존 Bubbly Lab의 04:30 KST 정리 작업도 유지한다.

종료 게임·질문 원문은 30일 뒤 정리한다. 사용자별 출제 이력과 최고 기록은 별도로 유지한다. 익명 플레이어 토큰을 지우거나 새 기기로 접속하면 같은 사람임을 식별할 수 없다. 계정 간 기록 이전은 초기 범위에 없다.

초기 판정 임계값은 근거 충분성 0.85, 예 확률 0.85 이상, 아니오 확률 0.15 이하다. 화면에 모델 확률을 정확도처럼 표시하지 않는다. 세션당 모델 호출 60회, 플레이어당 분당 20회, 전역 일일 호출 기본 상한 20,000회다. `TQ_DAILY_CALL_LIMIT`으로 전역 상한을 조절한다.

## UI와 에셋

서재 배경, 황동 버튼, 종이 패널을 실제 이미지 에셋으로 적용했다. 글자·정답·20개 눈금·순위는 별도 UI로 표시한다. 원본 PNG와 같은 크기의 무손실 WebP를 보존했고 UI 상태는 같은 에셋에서 밝기·눌림·선택 표현으로 만든다.

블록팡·루멘 시프트 효과음 10개를 복사해 전송·판정·성공·오답·종료·기록·랭킹에 연결했다. 판정의 아니오와 정답 오답은 서로 다른 소리를 사용한다. 음소거·볼륨 저장, 비활성 탭 중지, 중복 결과 소리 억제와 동작 줄이기 설정을 지원한다. 출처와 실제 크기는 [assets/manifest.json](assets/manifest.json)에 기록한다.

## 개발과 검증

```powershell
npm run build:twenty
npm run test:twenty
npm run test:twenty:browser
npm run preview:twenty
```

정적 미리보기는 `http://127.0.0.1:8089/twenty-questions/`다. 로컬 화면은 API `http://127.0.0.1:8787`에 연결한다. 별도 터미널에서 `npx wrangler dev --config wrangler.game-api.toml --var TQ_LOCAL:true --port 8787`로 API를 실행한다. 공용 AI의 서비스 바인딩은 remote로 연결하고 D1·게임 상태는 로컬에 둔다. 따라서 Cloudflare 로그인과 배포된 공용 진입점이 필요하며 실제 AI 요청 비용이 발생한다. 정적 미리보기만 실행한 상태에서는 판정 서버가 제공되지 않는다.

자동 브라우저 검사는 SQLite 기반 실제 게임 서버 로직과 고정된 테스트용 판정 응답을 결합한다. 실제 모델 검증은 별도로 실시하며 [QA.md](QA.md)에 구분해 기록한다. 공개 게임에서 가짜 판정을 대체 응답으로 사용하지 않는다.

서버 코드는 저장소의 `server/twenty-questions/`에 있다. `/server/*`는 Pages Function에서 404로 막고 `_routes.json`에 포함한다. 테스트·개발 서버에서도 같은 경로를 차단한다. 카탈로그 모듈을 브라우저 JS에서 가져오면 안 된다.

## 운영 반영 순서

1. 두 저장소의 `main`에서 검사·커밋·푸시
2. 깨끗한 `harem` 작업 트리와 `HEAD == origin/main` 확인 후 `wrangler.openrouter.toml`의 공용 Worker 반영
3. 같은 조건을 확인한 `archerlab-games`에서 `wrangler.game-api.toml` 반영. 새 Durable Object 마이그레이션 포함
4. Pages의 main 빌드 반영. 한영 URL·서버 파일 404·API 준비 상태 확인

새 D1 테이블과 초기 200개 카탈로그는 서버 초기화에서 멱등 생성한다. 기존 게임 테이블은 수정하지 않는다. 기존 공용 점수 API로 스무고개 점수를 제출하면 403으로 거부하며 연속 기록은 게임 서버만 계산한다.
