# 스무고개 1.0 검증 기록

검증일: 2026-10-28

## 실제 Microsoft-Decision-1 평가

기존 공용 AI Worker의 OpenRouter 비밀 설정을 사용하는 원격 미리보기에서 실행했다. 실제 응답 모델은 `microsoft/microsoft-decision-1-20261009`, 제공 경로는 Azure다. 게임과 같은 `judge`·응답 검증·임계값 코드를 사용했고 판정 키는 로그나 게임 파일에 복사하지 않았다.

평가 문항은 초기 정답 200개를 다루는 300개 한영 질문 쌍이다. 240쌍을 먼저 평가하고 따로 남겨둔 60쌍으로 독립 검증했다. 두 단계 사이에 프롬프트나 임계값을 조정하지 않았다. 실제 사용자의 모든 자유 질문을 대표하는 결과나 정확도 보장은 아니다.

| 구간 | 언어 | 질문 수 | 확정 예·아니오 정답 / 응답 | 판정 가능한 문항의 응답률 | 요청 오류 | 모델 호출 p95 |
| --- | --- | --- | --- | --- | --- | --- |
| 사전 평가 | 한국어 | 240 | 191 / 191 | 91.8% | 0 | 399ms |
| 사전 평가 | 영어 | 240 | 204 / 204 | 98.1% | 0 | 385ms |
| 독립 평가 | 한국어 | 60 | 50 / 50 | 96.2% | 0 | 475ms |
| 독립 평가 | 영어 | 60 | 52 / 52 | 100% | 0 | 387ms |

총 600개 중 497개를 예·아니오로 확정했고 이 검증셋에서 497개 모두 기대 판정과 일치했다. 사람이 판정 가능하다고 정한 520개 중 23개는 보류했다. 별도의 보류·복수 질문 문항 80개는 기대 처리와 일치했다. 지연은 원격 모델 호출 구간이며 사용자 기기의 전체 화면 응답 시간을 뜻하지 않는다.

원문 문항과 분할 기준은 서버 전용 `server/twenty-questions/evaluation-cases.mjs`와 [design/evaluation-notes.md](design/evaluation-notes.md)에 있다. 실행 결과 원본은 로컬 `tmp/twenty-questions-qa/live-calibration.json`, `live-holdout.json`에 보존했다.

## 실제 모델을 연결한 브라우저 플레이

별도의 로컬 SQLite 게임 데이터로 한국어 질문 → 영어 페이지 전환 → 영어 질문 → 정답 제출 → 연속 성공 1회까지 통과했다. 두 질문은 실제 모델을 호출했고 정답 제출은 서버의 이름 비교로 처리했다. 정답은 펭귄, 사용 기회는 3회였다. 이 검사는 운영 사용자의 기록을 생성하거나 수정하지 않았다.

실행 기록은 `tmp/twenty-questions-qa/live-browser.json`, 화면은 `live-en-mobile.png`·`live-success-mobile.png`에 보존했다. 실제 모델 호출 지연은 이 실행에서 1,224ms와 428ms였다.

추가로 Cloudflare Workerd의 실제 로컬 D1·Durable Object와 배포된 공용 AI의 원격 RPC를 연결해 요청 가로채기 없이 브라우저 플레이를 검증했다. 한국어 질문, 영어 전환, 영어 질문과 정답 제출로 성공·연속 기록 1회까지 통과했다. 결과는 `tmp/twenty-questions-qa/native-worker-browser.json`에 있다.

## 기능·경계 검사

실제 공용 텍스트 모델과 Microsoft 판정, 외부 출처를 연결한 보충 검사에서 초기 200개를 유지하면서 검증된 신규 개념 4개를 추가했다. 같은 날짜의 재실행도 중복 보충하지 않았다. 이 검사는 별도 로컬 SQLite에서 실행했으며 운영 D1에는 테스트 후보를 넣지 않았다. 실제 Edge 런타임에서 출처 응답 200도 확인했다. 근거가 부족하거나 잘못된 별칭을 가진 후보는 검증 단계에서 제외했다.

- 초기 카탈로그 200개, 한영 이름·동의어 충돌, 사실 카드 범위 검사
- 서버 규칙·실패 복구: 20번째 성공/실패, 보류·복수·중복 무차감, 질문 요청 한도 후 정답 제출, 모델 오류·일일 한도 시 만료 보정
- 중복·동시 요청: 한 판만 생성, 같은 요청 재전송의 차감·성공 중복 없음, 오래된 버전 거부
- 개인 최고 기록·연속 기록·총 사용 기회 동률 정렬, 사용자 점수 제출 거부
- 재출제 방지·목록 소진·신규 개념 추가, 30일 정리 후 출제 이력·최고 기록 보존
- 생성 검증 확률이 누락된 응답 거부, 카탈로그 성장 후 RPC 입력 바이트 제한 준수
- 오래된 초기 조회가 새 게임 상태를 덮는 문제 수정과 브라우저 회귀 검사
- 한국어 조합 입력 중 Enter 전송 방지, 언어 전환 시 게임·입력 초안·기록 유지

`test:twenty`의 카탈로그·서버 검사 25개가 통과했다. 별도 브라우저 자동화는 판정 응답만 고정한 테스트용 모델을 사용하고 실제 게임 로직과 SQLite를 실행했다. 이 결과와 위 실제 모델 평가를 구분한다.

## 화면·에셋·사운드

1440×1000, 320×568, 360×800, 390×844, 430×932, 768×1024, 844×390에서 한영 시작·진행·결과 흐름을 검사했다. 가로 넘침과 브라우저 예외가 없고 남은 눈금은 정확히 20개다. 대표 PC·모바일 화면을 직접 확인했다. 실제 휴대전화 키보드·이어폰의 최종 현장 검수는 별도 환경에서 필요하다.

생성 PNG 원본과 WebP는 같은 크기이며 무손실 변환 후 가시 픽셀 차이가 0이다. 재사용 효과음 10개는 원본 해시와 같다. Web Audio 재생, 결과별 음량·속도·재생 길이, 음소거·볼륨 저장·백그라운드 중지를 구현했다. 자동 브라우저 재생 검사가 청취를 통한 최종 마스터링 검수를 대신하지는 않는다.

포털은 신규 카드만 추가했다. 기존 10개 카드의 HTML·위치·폭·높이를 1440×1000과 390×844에서 작업 전후 대조해 동일함을 확인하고 화면도 저장했다. 기존 게임의 HTML·CSS·이미지·게임 로직은 변경하지 않았다. 포털 메타데이터의 게임 수와 신규 게임 링크만 갱신했다.
