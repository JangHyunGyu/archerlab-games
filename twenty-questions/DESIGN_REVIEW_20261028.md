Jev 공식 문서의 모델 ID·Decisions API·판정 형태·가격, Cloudflare 공식 문서의 UTC 스케줄 기준을 확인했다. 외부 근거는 기획서 해당 문단에 연결했다. 실제 모델 호출이나 한영 판정 품질 평가는 하지 않았다.

게임 테스트·빌드와 브라우저 시각 검사는 실행하지 않았다. 문서만 수정해 실행 화면 변경은 없으며 렌더링 전후 비교를 수행한 것으로 보고하지 않는다. 이전 기획서의 테스트·스크린샷 결과는 과거 기록으로 구분했다. 게임 구현 시 기획서의 검사 기준과 기존 UI 보존 규칙을 적용한다.

## 0.3 모델·랭킹 개정

Microsoft-Decision-1을 우선 모델로 지정하고 OpenRouter 경유와 Foundry 직접 호출을 구분했다. Microsoft 공식 문서에서 Noul·Choice 지원과 Foundry 호출 경로를 확인했으며 OpenRouter 모델 페이지에서 ID·표시 가격을 확인했다. Jev는 비교 후보로만 남겼다. 호출 코드·유료 평가·운영 설정은 실행하지 않았다.

랭킹은 개인 최고 연속 성공 횟수, 같은 횟수에서는 해당 기록의 총 사용 기회, 그다음 달성 시각 순으로 설계했다. 현재 연속 기록과 최고 기록을 분리하고 실패·포기·만료, 성공 직후 중단, 서버 장애, 중복 전송, 언어 전환, 정답 목록 교체의 처리 기준을 명시했다. 공용 랭킹 코드의 일반 정렬 기준과 달라 전용 서버 집계를 계획했다.

게임 안내 문구 29쌍은 그대로 유지했다. 모델·랭킹 기획 변경 후에도 키·플레이스홀더·상대 링크·문서 변경 범위 검사와 `git diff --check`를 다시 수행했다. 랭킹 서버나 화면을 구현한 것으로 기록하지 않는다.

## 0.4 사용자별 재출제 방지

매 판 무작위 선택을 사용자별 미출제 목록의 순차 소비로 변경했다. 매일 200개 공통 후보를 준비하고 동일 플레이어의 전체 출제 이력을 제외한 뒤 남은 개념의 순서를 한 번 섞는다. 성공뿐 아니라 실패·포기·만료한 개념도 다시 사용하지 않는다. 최근 7일 회피는 공통 후보 생성의 다양성 기준으로만 유지하고 사용자별 재출제 금지에는 기간을 두지 않았다.

날짜가 바뀌어도 같은 대상을 식별할 공통 개념 목록과 사용자별 출제 이력·순서 테이블을 설계했다. 세션 배정 시 이력·순서·활성 세션을 함께 확정하고 동시 요청과 재전송은 기존 세션에 복귀하도록 했다. 원문 로그 정리가 누적 이력을 지우지 않게 보관 규칙을 분리했다.

목록을 다 쓰거나 생성에 실패했을 때 이미 쓴 단어를 재사용하지 않는다. 신규 판은 기다리되 연속 성공 기록은 유지한다. 익명 ID가 달라지면 같은 사람임을 보장할 수 없으며 기기 간 보장에는 계정 연동이 필요하다는 제한을 명시했다.

기존 한국어·영어 문구는 변경하지 않았다. 문서 동기화·링크·변경 범위 검사와 `git diff --check`를 다시 수행했다. 실제 출제 로직·데이터베이스·게임 화면은 아직 구현하지 않았다.

## 0.5 디자인 방향

사용자가 요청한 고급스러운 스무고개 분위기에 맞춰 기존의 귀여운 분위기 지정을 탐정 서재로 변경했다. 봉인 문서·20개 눈금과 잉크색·아이보리·황동을 대표 요소로 삼고 화면별 배치, 한영 타이포그래피, 판정·정답 공개 연출, 사운드와 반응형 기준을 기획했다.

장식이 정답이나 분야를 암시하지 않도록 모든 문제에서 공통으로 사용한다. 눈금은 남은 기회만 나타내며 모델 확신도나 정답 접근 정도로 표시하지 않는다. 모든 실제 UI 문구·기회·기록은 코드로 렌더링하고 생성 시안의 이미지를 게임 화면으로 그대로 사용하지 않도록 구분했다.

이번 개정에서도 게임 안내 문구 29쌍은 그대로 유지했다. 문서 동기화·링크·변경 범위 검사와 `git diff --check`를 수행했다. 게임 화면 구현·배포·실제 시각 회귀 검사는 수행하지 않았다.
