# 스무고개 (Twenty Questions)

작성일: 2026-09-30

상태: 기획 단계. 게임 화면, API, D1 테이블, 정답 생성 스케줄러는 아직 구현하지 않았다.

프로젝트 경로: `archerlab-games/twenty-questions/`

## 1. 게임 개요

스무고개는 사용자가 자유롭게 질문하고, AI의 예·아니오 답변을 바탕으로 숨겨진 단어를 맞히는 웹게임이다. 익숙한 놀이 이름을 그대로 사용해 게임 방식을 쉽게 알 수 있게 한다. 화면은 귀엽고 편안한 분위기로 구성하며, 캐릭터 디자인과 이미지 제작은 구현 단계에서 결정한다.

| 항목 | 기획 |
| --- | --- |
| 장르 | 자연어 질문 기반 추리 게임 |
| 플랫폼 | 모바일·PC 웹 |
| 기본 언어 | 한국어 |
| 한 판 목표 시간 | 3~5분. 실제 플레이 후 조정 |
| 판단 모델 | OpenRouter의 TypeSafe Jev |
| 정답 공급 | 매일 생성하는 단어 200개 |
| 저장소 | Cloudflare D1의 게임 전용 테이블 |
| 핵심 규칙 | 질문과 정답 제출을 합쳐 20회, 힌트 없음 |

## 2. 대화에서 정한 방향과 설계 기본값

사용자 요청으로 정한 방향은 Jev의 Y/N 판단, 힌트 제외, D1 전용 테이블, 스케줄러를 통한 매일 200개 생성·교체, 폭넓은 단어 출제다. 이번 작업은 이 기획서를 작성하고 게시하는 데까지다.

정답 제출도 기회 1회를 쓰는 방식, 새벽 4시 갱신, 판정 보류 기준, 보관 기간은 앞선 논의를 바탕으로 잡은 설계 기본값이다. 구현과 플레이 검증 과정에서 조정할 수 있다. 정답 제출을 한 번으로 제한하는 규칙은 채택하지 않는다.

## 3. 한 판의 진행

1. 서버가 현재 활성화된 정답 200개 중 하나를 무작위로 선택한다.
2. 정답 이름, 의미, 특징, 인정할 표현을 게임 세션에 복사해 고정한다.
3. 사용자가 질문을 입력하면 서버가 Jev에 판정을 요청한다.
4. 판정 가능한 질문에는 예 또는 아니오를 표시하고 기회 1회를 차감한다.
5. 사용자는 언제든 정답 제출 모드로 전환해 단어를 입력할 수 있다.
6. 정답이면 즉시 성공한다. 오답이면 기회 1회를 쓰고 이어서 진행한다.
7. 20번째 행동이 정답이면 성공하고, 그렇지 않으면 실패한다. 종료 후 정답과 기록을 공개한다.

20회에는 질문과 정답 시도가 모두 포함된다. 질문 20회 뒤에 별도의 최종 제출 기회를 주지 않는다. 힌트 버튼, 힌트 데이터, 광고를 통한 힌트 제공은 넣지 않는다.

## 4. 질문과 정답 판정

| 입력 또는 상황 | 처리 | 기회 사용 |
| --- | --- | --- |
| 의미가 분명하고 사실로 판단 가능한 질문 | 예 또는 아니오 | 1회 |
| 복수의 독립 질문을 한 번에 입력 | 질문을 나눠 입력하도록 안내 | 없음 |
| 주관적이거나 정답 자료가 부족한 질문 | 판정 보류 | 없음 |
| 같은 질문을 같은 의미로 반복 | 확인 가능한 경우 이전 결과 재사용 | 없음 |
| 정답 제출 | 서버에서 정답·동의어와 비교 | 1회 |
| API 장애, 응답 형식 오류, 시간 초과 | 실패 안내 후 재시도 | 없음 |
| 종료된 게임에 추가 입력 | 접수하지 않음 | 없음 |

단순한 질문 표현만으로 정답 제출 모드를 자동 변경하지 않는다. 사용자가 선택한 입력 모드를 기준으로 처리해 의도하지 않은 승패 판정을 막는다.

정답 비교는 앞뒤 공백과 문자 정규화, 등록된 동의어를 기준으로 한다. 부분 문자열 일치나 무조건적인 유사도 판정은 사용하지 않는다. 상위 개념, 다른 종, 이름이 비슷한 사물을 잘못 정답으로 인정하지 않아야 한다. 띄어쓰기·오탈자 허용 범위는 한국어 사례를 모아 별도로 정한다.

## 5. 출제할 단어의 범위

사용자는 별도 카테고리 선택 없이 모든 분야의 단어를 만난다. 내부 분류는 생성 편중 방지와 통계에 사용한다.

동물, 식물, 음식, 생활용품, 도구, 장소, 직업, 인물, 캐릭터, 작품, 자연현상, 과학 용어, 추상적인 개념 등을 후보로 허용한다. 익숙한 단어를 중심으로 구성하되 특정 분야의 고정 목록으로 제한하지 않는다.

출제 가능 여부는 다음 기준으로 판단한다.

- 하나의 의미나 대상을 특정할 수 있는 단어
- 예·아니오 질문으로 구분할 만한 특징이 있는 단어
- 검증 가능한 기본 사실을 확보할 수 있는 단어
- 정답 이름과 동의어의 경계가 분명한 단어

동음이의어는 단어와 의미를 함께 저장한다. 인물과 작품은 공식 이름과 널리 쓰는 별칭을 기록한다. 추상 개념도 허용하지만, 개인의 가치 판단이 필요한 질문은 보류한다. 조사·어미·임의의 문자열, 실체가 확인되지 않은 생성 결과는 일반 출제에서 제외한다.

매일 200개 안에서는 같은 대상과 중복 표현을 제거한다. 날짜가 다른 목록 사이에서는 최근 7일간 나온 대상을 우선 피한다. 이 기간은 초기 기본값이며, 중복 회피 때문에 지나치게 생소한 단어를 억지로 채우지 않는다. 모든 날에 걸친 영구적인 중복 금지는 적용하지 않는다.

## 6. 모델의 역할

### Jev: 게임 중 판단

Jev는 자유 문장 생성 대신 정해진 판단 결과와 확률을 반환하는 모델이다. 문서 확인 시점의 모델 ID는 `typesafe/jev-1.13`이며, `POST https://openrouter.ai/api/alpha/decisions`로 호출한다. 운영 전에는 지원 모델과 API 명세를 다시 확인한다.

서버가 보내는 정보는 고정된 정답의 의미·사실 카드, 사용자 질문, 필요한 이전 판정이다. 질문 유효성, 자료 충분성, Y/N 여부를 독립된 질문으로 요청하고 서버가 결과를 조합한다. Noul은 예일 확률을 반환하고, Choice는 미리 정의한 선택지 중 하나를 반환한다. 같은 요청에 넣은 판단들은 서로의 결과를 참조하지 않는다.

확률 0.5를 기준으로 무조건 Y/N을 결정하지 않는다. 사실 카드의 정보가 충분한지 먼저 확인하고, 실제 한국어 평가 결과로 정한 임계값을 적용한다. 확신도는 실제 정답률을 보장하지 않으므로 화면에 정확도 수치로 표시하지 않는다.

예·아니오, 판정 보류와 오류 안내는 게임이 정해진 문구로 표시한다. 사용자 질문은 판단 대상 데이터로 취급하고, 질문 안의 지시로 정답이나 게임 규칙을 변경하지 않는다.

### 생성형 모델: 하루 정답 목록 작성

Jev와 별도의 생성형 모델이 단어와 사실 카드를 만든다. 모델은 한국어 품질, 구조화 응답 지원, 비용을 비교한 뒤 선정한다. 이번 기획에서 특정 생성 모델은 확정하지 않는다.

생성 결과에는 단어, 의미 설명, 분야, 동의어, 기본 특징, 난이도 제안을 포함한다. 모델이 작성한 사실을 곧바로 검증된 사실로 간주하지 않는다. 인물·작품·전문 용어처럼 오류 가능성이 있는 항목은 신뢰할 수 있는 자료와 대조하고, 확인이 어려우면 후보에서 제외한다. 출처 링크가 실제로 해당 사실을 뒷받침하는지도 확인한다.

## 7. 매일 200개 생성과 교체

Cloudflare Cron Triggers로 한국 시간 매일 새벽 4시에 생성 작업을 시작한다. Cron은 UTC 기준이므로 표현식은 `0 19 * * *`다. 새벽 4시는 생성 시작 시각이며, 교체 시각은 200개의 검사가 완료된 시점이다.

1. 한국 시간 기준 날짜를 작업 키로 만들고, 해당 날짜의 완료 작업이 있으면 종료한다.
2. 작업 소유권을 확보하고 준비 상태의 새 묶음을 만든다. 중복 실행은 기존 진행 상태를 확인한다.
3. 분야를 분산해 25개 안팎씩 생성하고 중간 결과를 저장한다.
4. 형식, 의미, 동의어, 중복, 사실 카드의 품질을 검사한다.
5. 탈락한 항목 수만큼 보충하되 재시도 횟수와 비용 상한을 적용한다.
6. 사용 가능한 정답이 정확히 200개일 때만 해당 묶음을 완료 상태로 만든다.
7. 활성 묶음 ID를 한 번에 바꿔 신규 게임에 적용한다.

생성과 검사는 활성 목록 밖에서 수행한다. D1 트랜잭션 안에서 외부 모델 응답을 기다리지 않는다. 최종 완료 처리와 활성 ID 전환은 원자적으로 실행하고, 오래된 작업이 나중에 끝나 최신 목록을 덮어쓰지 않도록 날짜와 현재 상태를 검사한다.

실패하면 기존 활성 목록을 계속 사용한다. 실패한 작업은 저장된 진행 상태부터 이어서 재시도하며, 무제한으로 모델을 호출하지 않는다. 최초 운영 때는 검사를 통과한 초기 200개를 미리 준비한다. 활성 목록이 전혀 없으면 게임 시작을 잠시 막고 재시도 가능한 상태를 반환한다.

생성이 실행 환경의 제한 시간을 넘을 가능성이 있으면 Cloudflare Workflows 또는 Queues로 작업을 나눈다. Cron은 작업 시작을 담당하고, 분할 작업은 완료·재시도 상태를 기록한다. 실제 실행 방식은 구현 시 런타임 제한과 측정 시간으로 결정한다.

## 8. D1 전용 테이블 설계

기존 게임과 이름이 충돌하지 않도록 `twenty_questions_` 접두어를 사용한다. 아래는 논리 설계이며, 실제 마이그레이션은 구현 단계에서 작성한다.

| 테이블 | 주요 데이터 | 목적 |
| --- | --- | --- |
| `twenty_questions_answer_batches` | ID, 한국 기준 날짜, 상태, 유효 정답 수, 생성 모델·버전, 비용, 재시도 수, 작업 소유권·만료 시각 | 일별 생성 작업과 재실행 관리 |
| `twenty_questions_answers` | ID, 묶음 ID, 단어, 의미 키, 분야, 동의어 JSON, 사실 카드 JSON, 검증 근거, 검증 상태 | 정답 200개 저장 |
| `twenty_questions_settings` | 설정 키, 값 | 현재 활성 묶음 ID와 운영 설정 |
| `twenty_questions_sessions` | ID, 익명 소유자 식별값, 정답 스냅샷, 묶음 ID, 사용 횟수, 상태, 버전, 만료 시각 | 진행 중인 게임과 정답 고정 |
| `twenty_questions_turns` | 세션 ID, 요청 ID, 입력 모드, 입력, 판정, 확률, 차감 여부, 모델 버전, 비용 | 질문 기록과 중복 요청 방지 |

생성 날짜와 세션별 요청 ID에는 중복 방지 제약을 둔다. 같은 묶음 안의 정답은 단어와 의미를 정규화한 키로 중복을 검사한다. 활성 묶음과 세션 조회에 필요한 인덱스를 둔다.

초기 보관 기본값은 이전 정답 묶음 30일, 종료된 게임과 질문 로그 30일, 미완료 세션 유효기간 24시간이다. 진행 중 세션은 정답 스냅샷을 사용하므로 목록 교체 후에도 같은 기준으로 판정한다. 삭제 작업은 활성 묶음과 유효한 참조를 보호한다. 오래된 통계가 필요하면 원문 질문 없이 집계값만 남긴다.

## 9. 서버와 API

게임 화면 → 게임 서버 → D1 및 OpenRouter → 판정 검증 → 화면 표시 순서로 동작한다. 기존 공용 API Worker에 경로를 추가할지 별도 Worker로 분리할지는 구현 전에 현재 라우팅과 운영 구성을 확인해 결정한다.

| 제안 경로 | 처리 |
| --- | --- |
| `POST /api/twenty-questions/games` | 활성 목록에서 정답 선택, 세션 생성 |
| `GET /api/twenty-questions/games/:id` | 본인 게임의 공개 상태와 기록 조회 |
| `POST /api/twenty-questions/games/:id/questions` | 질문 유효성·Y/N 판정 |
| `POST /api/twenty-questions/games/:id/guesses` | 정답 제출과 승패 판정 |
| `POST /api/twenty-questions/games/:id/give-up` | 포기 처리 후 정답 공개 |

API 키는 서버 비밀 설정에 저장한다. 게임 종료 전에는 정답·동의어·사실 카드·모델 요청 원문을 클라이언트에 보내지 않는다. 세션 소유권을 확인하고, 요청 ID와 세션 버전으로 재전송과 동시 입력이 기회를 두 번 차감하지 않도록 한다.

AI 판정이 끝난 뒤 세션 상태를 다시 확인하고 기록·횟수·승패를 함께 확정한다. 이미 끝난 게임이나 오래된 버전의 판정은 반영하지 않는다. 질문 길이, 호출 빈도, 일별 모델 비용에 상한을 둔다. 기회를 차감하지 않는 보류·오류 요청에도 호출 제한은 적용한다.

정답 목록 갱신으로 게임 내 점수가 바뀌지 않도록 한다. 최초 버전은 성공 여부와 사용 횟수를 기록하며, 전역 랭킹이나 복잡한 점수 공식은 후속 검토로 남긴다.

## 10. 화면과 사용성

- 시작 화면: 게임 이름, 간단한 규칙, 시작 버튼
- 게임 화면: 남은 기회, 질문·답변 기록, 입력창, 질문·정답 제출 모드, 포기
- 결과 화면: 성공·실패, 정답과 의미, 사용 횟수, 질문 기록, 다시 시작

귀엽고 편안한 분위기로 표현하되 입력과 기록 읽기를 우선한다. 모델명이나 판정 확률 같은 구현 정보는 기본 게임 화면에 노출하지 않는다. 초기에는 정답의 분야를 공개하거나 선택하게 하지 않는다.

모바일 키보드가 열려도 입력창과 전송 버튼에 접근할 수 있어야 한다. 작은 휴대전화, 큰 휴대전화, 태블릿, 데스크톱의 가로·세로 화면을 확인한다. 터치 대상은 44 CSS 픽셀 이상으로 두고, 키보드 조작·포커스 표시·동작 줄이기 설정을 지원한다.

이번 문서 배포에서는 기존 포털의 카드, 메뉴, 스타일, 순서를 변경하지 않는다. 게임 구현이 완료되기 전에는 포털에 실행 가능한 게임으로 등록하지 않는다.

## 11. 비용과 운영 지표

2026-09-30 확인한 Jev 1.13 표시 요금은 입력 100만 토큰당 $0.042, 출력 토큰 무료다. 요청당 전체 입력 1,000토큰, 게임당 20회 호출을 가정하면 약 $0.00084/판이다. 이 수치는 예시이며 모델 요금 변경, 정답 생성·사실 검증·재시도·보류 요청, 서버와 D1 비용은 별도다.

운영에서는 정답 생성 비용과 플레이 판정 비용을 분리해서 기록한다. 생성된 후보 수, 검증 탈락률, 중복률, 200개 완료 여부, 갱신 지연, 판정 보류율, 정답률, 평균 사용 횟수, 응답 지연을 확인한다. 확률이 높은 오답도 표본 검사 대상으로 삼는다.

## 12. 구현 순서와 완료 기준

1. 한국어 질문 평가: 부정문, 동음이의어, 복수 질문, 주관적 질문, 지시문이 포함된 질문 등 약 300개로 Jev 판정 검증
2. 정답 생성 검증: 후보 생성과 사실 확인, 중복 검사로 실제 출제 가능한 200개 확보
3. D1와 일별 생성 작업: 중단 복구, 동일 날짜 재실행, 부족한 수량, 비용 상한, 원자적 교체 검증

5. 게임 UI: 질문·정답 제출·포기·복귀·종료 흐름과 반응형 화면 검증
